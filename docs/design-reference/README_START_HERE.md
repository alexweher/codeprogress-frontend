# CodeProgress — полный пакет дизайнерских наработок

**Состав:** продуктовая UX-концепция, дизайн-система, спецификации, интерактивные HTML-прототипы, desktop/mobile-макеты, техническое задание №52 и отчёты о ранее внедрённых изменениях.

## С чего начать

1. `01_Product_Concept_and_Phase_A/CodeProgress_Design_Blueprint_v2.md` — общая стратегия, метрики и требования.
2. `01_Product_Concept_and_Phase_A/CodeProgress_UX_Prototype.html` — интерактивный прототип главного экрана (откройте локально в Chrome).
3. `02_Phase_B_Topics_Tasks_Design/CodeProgress_PhaseB_Design_Spec.md` — подробные требования к темам и задачам.
4. `02_Phase_B_Topics_Tasks_Design/CodeProgress_PhaseB_UX_Prototype.html` — прототип темы и задачи.
5. `02_Phase_B_Topics_Tasks_Design/CodeProgress_PhaseB_Codex_Task_52.md` — готовая постановка Codex.

## Структура

- `01_Product_Concept_and_Phase_A/` — стратегия, интерактивный прототип, превью и макеты для desktop/mobile.
- `02_Phase_B_Topics_Tasks_Design/` — спецификация и задание №52, HTML-прототип, превью и 5 макетов экранов.
- `03_Implementation_Reports/` — отчёты по локализации, первому редизайну и Phase A.

## Важно для Codex

Материалы прототипов содержат демонстрационные данные и описывают желаемое поведение; их нельзя использовать как источник пользовательских записей. Реализуйте дизайн в существующем React/TypeScript проекте. Не заменяйте действующие API-контракты и не копируйте demo-значения в production. Сохраняйте локализацию ru/en, auth/JWT in memory, пользовательские данные и незакоммиченные изменения.

Чтобы Codex видел материалы, распакуйте ZIP в отдельную папку (например `docs/design-reference/`) в его локальной рабочей области либо приложите нужные файлы к чату Codex. Сам по себе ZIP, находящийся в чате ChatGPT, не появляется в рабочей директории Codex.

Этот архив не содержит настоящие данные пользователей, пароли, JWT или скриншоты личного аккаунта.
